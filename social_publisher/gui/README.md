# Оконный интерфейс: «Публикатор клипов и фото»

Часть программы с кнопками для Windows. Внутри — та же логика публикации,
что и в консольном варианте: входные данные → блокноты по сервисам →
проверка → запуск.

## Запуск

Двойной клик по **`Запустить публикатор.bat`** в корне проекта (или по
`run_gui.pyw`). Консоль не открывается.

Из командной строки:

```bat
python -m social_publisher.gui
python -m social_publisher.gui --home C:\clips
```

Нужен Python 3.11+ с tkinter — это стандартный компонент установщика
python.org (галочка **«tcl/tk and IDLE»**). Ничего дополнительно ставить не нужно,
кроме Playwright, если хотите браузерный режим:

```bat
python -m pip install playwright
python -m playwright install chromium
```

## Как работать

1. **Входные данные…** — заполняются **один раз**.
   * Telegram: токен бота и `@канал`;
   * VK: ключ доступа и id сообщества;
   * YouTube: `client_secret.json` и кнопка **«Войти в Google»**;
   * Rutube: токен (если есть).
   Остальные сервисы входа не требуют — кнопка **«Войти в браузере»**
   открывает окно, где вы один раз входите в аккаунт, профиль сохраняется.
   Данные пишутся в `secrets.toml` (только владельцу) и `setup.json`.

2. **Отдельное окно-блокнот на каждый сервис.**
   Двойной клик по строке сервиса (или «Открыть блокнот», «Открыть все блокноты»).
   В блокноте:
   * слева — файлы (**Добавить файлы…**) и общие поля: теги, категория, ссылка;
   * справа — текст: **первая строка = заголовок**, дальше описание;
   * несколько постов в одном блокноте разделяются строкой `---`;
   * если первая строка — просто `.`, заголовок берётся из общего поля;
   * подписи к фото: `путь_к_файлу | подпись` — попадут в описание поста.

3. **Проверить** — таблица «Пост · Сервис · Файл · Результат»: есть ли файлы,
   не превышены ли лимиты, готов ли сервис (заполнены ли входные данные).
   Ошибки — красным, предупреждения — коричневым.

4. **Запустить** — публикация. Галочки:
   * «Только проверка (ничего не публиковать)» — включена по умолчанию, удобно
     для первого прогона;
   * «Повторить уже опубликованное» — игнорировать журнал;
   * «Без подтверждений» — публиковать без вопросов (осторожно);
   * «Режим»: `auto` (токен → API, иначе браузер), `api`, `browser`, `manual`.

   Перед каждой отправкой появляется вопрос с текстом и файлами поста.
   Всё, что произошло, видно в журнале внизу окна и в кнопке **«Журнал»**.

## Что где лежит

| Файл | Что это |
|---|---|
| `config.toml` | настройки (режим, браузер, категория YouTube) |
| `secrets.toml` | токены и входы — создаётся окном, в git не попадает |
| `setup.json` | необязательные поля окна входов (имена, пути) |
| `plan.toml` | собранный план; его же понимает консольная команда `run` |
| `state/journal.jsonl` | журнал публикаций |
| `state/screenshots/` | скриншоты ошибок браузерного режима |
| `state/browser-profile/` | сохранённые входы в браузере |

План можно собрать в окне, а опубликовать консолью — и наоборот:

```bat
python -m social_publisher run plan.toml --yes
```

## Если что-то не так

* **Окно не открывается** — рядом появится `gui_error.log`; чаще всего в сборке
  Python нет tkinter (переустановите Python с python.org и галочкой tcl/tk).
* **«Ни один сервис не настроен»** при запуске — сначала «Входные данные…».
* **«Не готов» у сервиса** — проверьте входные данные: красный текст в окне
  входов подсказывает, чего не хватает.
* **Браузерный режим не открывается** — нет Playwright: `pip install playwright`
  и `python -m playwright install chromium`, либо `channel = "msedge"` в конфиге.
* **Селекторы устарели после редизайна сайта** — `python -m social_publisher learn <сервис>`
  и поправьте `selectors.local.json` (см. основной README).

## Устройство

```
social_publisher/gui/
  __main__.py      запуск окна (python -m social_publisher.gui)
  main_window.py   главное окно: таблица сервисов, проверка, журнал, запуск
  pad_window.py    окно-блокнот одного сервиса
  setup_window.py  окно «Входные данные» + входы в аккаунты
  services.py      список сервисов, подписи, лимиты (без tkinter)
  plan_builder.py  блокнот → план → plan.toml (без tkinter)
  tasks.py         входы, проверка, публикация в фоне (без tkinter)
```

Всё, кроме трёх окон, не зависит от tkinter и покрыто тестами
(`social_publisher/tests/test_gui_logic.py`, 22 теста). Окна тоже проверяются —
на заглушке tkinter (`tests/fake_tk.py`), поэтому работают и на машинах без
графической среды в CI.
